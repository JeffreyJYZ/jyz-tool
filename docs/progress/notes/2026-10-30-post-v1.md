# 2026-10-30 — after v1: machine surfaces

Everything added after the v1 milestone report. Same day, version line `0.1.0-alpha.3` → `alpha.4`.

## Landed

- **CLI JSON-RPC** — `jyz serve` reads newline-delimited JSON-RPC 2.0 on stdin and answers on stdout; methods are capability names; it resolves argv and never spawns. `listCapabilities()` in core is the manifest, and `serve` is hidden from help but still a core verb.
- **MCP** — 15 tools including `jyz_watch`/`jyz_cancel` with progress frames, plus `jyz://config` and `jyz://capabilities` resources served over `resources/list` and `resources/read`. Unknown URI maps to `-32602`.
- **Desktop bridge** — `jyz_call` and `jyz_version` Tauri commands spawn `jyz serve`, one frame each way, child killed after. The window's method list is derived from the capability manifest (`methodsFromManifest`, `groupByKind`), grouped by kind.
- **opencode seam** — `resolveServer` (flag → env → default `http://127.0.0.1:4096`), `listSessions`, `sendPrompt`, `OpencodeError`; exposed as hidden `jyz oc <action> [...text]`.
- **`--json`** — one document on stdout for `config show|get|path|check`, every dispatch verb, `create`, and the toolchain verbs; exit codes unchanged; prose moves to stderr.
- **Release tooling** — `verify-release` (pure `checkAssets`, real run), `release-notes` (git history → markdown), `alpha-release` (gates → bump → commit → tag, `--dry-run`, `--push`), `bench` (p50/p95 startup and dispatch).
- **Toolchain coverage** — eslint, clang-tidy, clang-format, rustfmt, prettier, clang, cargo, plus `paths` argument and check-mode variants.
- **CI** — `bun run test` added (it was missing), a `rust` job running `cargo fmt --check` and `cargo check --locked`, and `rustfmt.toml` with `hard_tabs` so Rust matches house style.

## Traps recorded

- `cac` v7 has no nested commands: `command("oc sessions")` never matches. Use one command with a positional action and `[...rest]` for variadic args.
- Tauri v2 rejects unknown ACL entries: `allow-jyz-call` in `capabilities/default.json` fails `cargo check` unless the app defines that permission. App commands need no entry.
- `bun test` can print "0 fail" and still exit 1 when a test leaves `process.exitCode` set. Restore it to `0`, never to a captured value.
- A tracked path containing a newline or quote breaks Windows checkout before any CI step runs; `scripts/test/tracked-paths.test.ts` now fails on that class of name.
- Free-tier dispatches die account-wide at once; the Vercel `beam-free` twin needs `reasoning_content` on prior turns, so only cross-model resumes fail there.

## Still open

- Desktop parity is a manifest test, not a UI walkthrough.
- `--git github` remains stub-tested only.

## v2 close-out, alpha.6

- **Desktop installer carries the CLI.** `bundle.externalBin: ["binaries/jyz"]`; `packages/desktop/scripts/stage-sidecar.ts` compiles the CLI for the rust host triple into `src-tauri/binaries/jyz-<triple>` (gitignored) and `bun run build` chains it. The shell resolves a sibling `jyz` before `PATH`, so an installed app never depends on the user's shell.
- **Three desktop screens**: call runner, config viewer (`config show` rendered as key/value/source), opencode panel (`jyz oc sessions --json`, prompt send, 5 s watch that marks changed session ids).
- **`jyz oc --json`** prints one document; prose output is byte-identical to before.
- **MCP distribution**: `@jyz/mcp` declares a `jyz-mcp` bin, `files`, engines and publishConfig (still `private`), and the release builds `mcp-<version>.tgz` plus one compiled binary per target.
- **Release gate**: the publish job runs the parity test and asserts a non-empty capability manifest before uploading.
- **Click-through**: the page was driven in a browser with `__TAURI_INTERNALS__` stubbed — tabs switch, Run returns a frame, Config renders two rows, opencode lists two sessions and reports `sent to ses_alpha`.

Traps found: a `const` reached by a function called before its initializer is a TDZ `ReferenceError`, so the first render now runs last; biome flags `useButtonType` as an error in HTML-inlined markup.

## opencode SDK adoption, alpha.8

- **The seam runs on `@opencode/client` 2.2.3, pinned exact.** `listSessions` uses `session.list({ parentID: null, order: "desc", limit: 50 })` and unwraps `{ data, cursor }`; `sendPrompt` uses the flat `{ sessionID, text }`; `subscribeEvents` wraps `event.subscribe` and maps each frame to `{ type, sessionID, summary }`.
- **Reference is the live client, not guesswork**: `~/dev/apps/opencode-tauri-client/docs/opencode-api.md` documents the surface, the one-stream-per-server event contract, and the traps (`time.updated` is epoch milliseconds, `session.prompt` is flat, the generated input types are codegen artifacts needing one documented cast).
- **`jyz oc watch [--session] [--json] [--once] [--timeout ms]`** prints one line per event; `--timeout` bounds it so nothing can hang a caller.
- **Verified over real HTTP**, not only stubs: two local stand-in servers proved `sessions`, `prompt` and `watch` end to end.

Traps: `^2.0.29` resolves 2.2.3, so take `latest` (2.2.3 at the time) rather than a range that can drift under you; and a subagent that reports "green" can leave a test file at 0 bytes — check the file, not the report.

## Self-update, alpha.10

- **`tauri-plugin-updater` 2** with `bundle.createUpdaterArtifacts`, a pubkey from `~/.config/jyz/updater.key.pub`, and `endpoints: ["https://github.com/JeffreyJYZ/jyz-tool/releases/latest/download/latest.json"]`.
- **Two Rust commands**: `jyz_update_check` returns `{ current, version, notes } | null`, `jyz_update_install` downloads, installs and restarts. Check never downloads; a failed install never restarts.
- **In-window banner** above the tab strip: `update available: <version>` + Install, shaped by `describeUpdate` in `src/updates.ts` so it is unit-tested. A machine without a release endpoint silently shows nothing.
- **Three release traps, all measured**:
    - `latest.json` is per build and names only that build's platform, so `release.ts` writes `latest-<platform>.json` partials and `scripts/updater-manifest.ts` merges them; a shared filename would have let one job's manifest win.
    - the bundles' `0.1.0` version sorts **above** `0.1.0-alpha.N`, so the merge also restamps the version from `package.json`; without it every alpha offers to update to itself forever.
    - `cargo check` generates `src-tauri/gen/schemas/*.json`, which biome then tries to format and fails the lint gate — `!packages/desktop/src-tauri/gen` is now excluded.
- Verified in the browser: `bun scripts/ui-walkthrough.ts` reports 6/6 steps including `update available: 9.9.9`.

## Local alpha releases, alpha.10

Quarry's strategy, adopted: alphas are built, signed and published on this Mac; the CI matrix only serves non-alpha tags.

- `scripts/release-local.ts`: gates → signed `--bundles app` build → `hdiutil` dmg (no Finder) → `release.ts` + `updater-manifest.ts` → signature/mtime refusals → `gh` publish → verify.
- `scripts/updater-manifest.ts --partial|--merge`: Tauri writes the `.sig`, never `latest.json`, so the manifest is written here; CI's publish job merges the per-platform partials.
- `verify-release` accepts a macOS-only asset set; `--require-all` keeps the four-platform demand for stable releases; every release job carries `if: !contains(github.ref_name, '-alpha')`.

Traps, all measured while running it:

- Tauri does not write `latest.json` at all — only `tauri-action` does. Three CI jobs died on a file that cannot exist.
- Release assets are downloadable only on a public repo. `jyz-tool` is private, so `releases/latest/download/latest.json` returns 404 for an installer, and self-update cannot work until the repo is public or the manifest is hosted somewhere public.
- `/releases/latest/` skips prereleases, so an alpha must be published _without_ `--prerelease` and with `--latest` (what Quarry does) or its own update endpoint misses it.
- `release.ts` had been copying only `.sig` from the bundle, never the `.app.tar.gz` the signature covers; and `--skip-build` skipped dmg creation because it lived inside the build branch.
